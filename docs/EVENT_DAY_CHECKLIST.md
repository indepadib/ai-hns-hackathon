# Jour J — Check-list opérationnelle (28 novembre 2026)

Cette fiche ne contient aucun code d'accès, dossier candidat, adresse de contact ou résultat réel. Les horaires opérationnels sont à confirmer par l'organisation. Ne pas la considérer comme une preuve de recette physique.

## Avant ouverture — GO / NO GO
- [ ] Organisation : confirmer le planning officiel et le responsable de chaque espace.
- [ ] Technique : relever le commit publié, le deploy ID Netlify et le dernier deploy sain restaurable ; vérifier le domaine ai.hns.ma.
- [ ] RH : ouvrir le back-office avec un compte autorisé ; vérifier les compteurs, décisions et accès CV en lecture seule.
- [ ] RH : vérifier les invitations et confirmations réelles, sans créer de doublons ni réexpédier automatiquement.
- [ ] Accueil : tester une caméra sur Android et iOS, ainsi que la saisie manuelle, avec un pass de test autorisé et isolé.
- [ ] Organisation : vérifier les horaires de déblocage en lecture seule ; utiliser la simulation isolée pour parcourir toutes les missions.
- [ ] Mentors : confirmer leurs affectations et accès nominatifs, sans partager de clé administrateur.
- [ ] Jury : ouvrir son espace avec son propre accès ; vérifier la grille et la disponibilité de la restitution.
- [ ] Réseau : vérifier Wi-Fi, partage de connexion de secours, prises, chargeurs et ordinateur de remplacement.
- [ ] Répétition : réaliser le parcours complet en staging avec données fictives ; ne pas créer de faux dossiers dans le registre réel.

## Pendant l'événement
| Incident | Action immédiate | Vérification avant reprise |
| --- | --- | --- |
| Caméra inaccessible | Saisir le code d'invitation dans l'accueil RH | Présence confirmée par le serveur |
| Code invalide ou personne absente du registre | Orienter vers les RH, vérifier invitation et identité selon la procédure validée | Aucun contournement des droits ni doublon |
| Wi-Fi indisponible | Basculer sur connexion de secours ; conserver une trace temporaire des arrivées dans un registre RH protégé | Réconcilier une seule fois les présences après rétablissement |
| Sauvegarde en erreur | Ne pas fermer/recharger ; utiliser la copie ou le téléchargement JSON de secours | Version enregistrée vérifiée avant de reprendre |
| Conflit binôme | Conserver les modifications non enregistrées ; coordonner avec le partenaire et l'organisation | Version du dossier confirmée ; ne pas écraser aveuglément |
| Mentor sans accès | Vérifier le périmètre avec l'administrateur | Accès nominatif, uniquement aux candidats attribués |
| Jury : erreur de sauvegarde | Garder les notes à l'écran ; vérifier le statut et le dossier | Évaluation effectivement enregistrée, pas de double saisie |
| Démo indisponible | Demander une preuve reproductible ou une exécution locale ; consigner la limite | Ne pas inventer un résultat de test |
| Panne générale | Suspendre les actions sensibles et prévenir le responsable technique | Restaurer le dernier code sain si nécessaire, puis tester les accès ; le rollback ne restaure pas les données |
